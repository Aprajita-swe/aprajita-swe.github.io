From the field to the agent loop

About

My career started where data is hardest to get: on riverbanks, in hatcheries and in fish-feeding trials. I learned to design studies, collect samples, clean records that never match, and explain results to the people who run the facilities.

At Chalmers, I lead the analysis for Klimatkläckeri, a water-quality and microbial dynamics monitoring programme at three fish farms, with Vattenfall, RecirkFisk PO and the Swedish Veterinary Agency (SVA). It brings together water chemistry, DNA sequencing of about 14,000 microbial taxa, and weather and river-discharge data. This kind of data runs through any industry built on sensors, lab tests and inspections, and energy is one of them.

Projects

Portfolio

As an AI enthusiast, I build these projects to learn by doing. Each one takes messy real-world data, validates it, gives an LLM tested tools to work with it, and measures whether the answers are right.

01 · Agents + toolsBuilt

AquaAgent

A Deep Agent for water-chemistry analysis. It fetches lab records through my own MCP server, plans its steps, writes its own Python analysis script, runs it, and saves the plots.

Result: the agent produces the seasonal plots on its own, fully offline on a local model.

Learned: a small local model follows a method much better when it is written down. A skill file with the seasonal-analysis rules and a strict "write the script to a file, then run it" instruction made the agent's analyses reproducible.

02 · Document AIBuilt

ReceiptAgent

Turns receipt images into validated JSON (merchant, date, total, line items). OCR reads the image, and a local LLM extracts the fields inside a LangGraph loop. When the output fails validation, the model gets the error back and corrects itself, up to three times.

Result: the LLM extracted every amount correctly on the test receipts, and invalid outputs failed safely.

Learned: OCR, not the LLM, was the weak point: it dropped å, ä and ö. Next I'll compare it with a vision model that reads the image directly.

03 · Multi-agentBuilt

WaterGuide Crew

Three CrewAI agents write a seasonal water-quality report for each farm. A data analyst summarises lab data through my MCP server, a guidelines specialist checks it against rainbow trout guideline values, and a writer produces an operator report with an OK, WARNING or ALERT status.

Result: verified seasonal reports for three farms, with every number matching the database. When a tool failed, the agents reported the error instead of inventing values.

Learned: small local models work best with one narrow job per agent and the maths kept in tools. The agents also have to run inside the MCP connection, or the tools fail.
